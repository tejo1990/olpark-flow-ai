## 2. 발표 심사 대비 핵심 예상 질문 7선 & 30초 방어 답변 스크립트

### Q1. [2차 외부] “네이버지도나 티맵에도 혼잡도 그래프가 나오는데, 굳이 이 서비스를 써야 할 이유가 있습니까?”
> **30초 방어**: “맞습니다. 일반 평일·평균 교통량에서는 GPS 빅데이터를 가진 네이버지도·티맵이 우위이며, 저희는 범용 지도앱을 대체하려는 게 아닙니다. 다만 범용 지도앱은 **‘과거 단순 요일 평균’**만 보여줄 뿐, 공단만이 가진 **‘대형 공연 관람객 수(0~26,398명)’와 ‘공원 내부 11개 세부 구역(P1A~P11) 간 26.5%p 공간 편중’**, 그리고 **공단 담당자용 동시대관 시차·CO₂ ESG 시뮬레이터**는 제공하지 못합니다. Olpark Flow AI는 바로 그 **공연 특수일·공원 내부 미시 분산·B2G 의사결정** 사각지대에 특화된 공공데이터 디지털 트윈입니다.”

### Q2. [1차 내부] “우리 실시간 주차 API는 공원 전체 합계(`parking_sum`) 하나만 제공하는데, 3D 지도의 `P1A~P11` 구역별 퍼센트는 실제 센서값입니까?”
> **30초 방어**: “아주 정확한 지적이며, 기획서 3-1절에도 투명하게 명시했습니다. 현재 실시간 API는 전체 합계만 제공하므로, 3D 기둥의 구역별 부하는 공단이 개방한 **주차장 혼잡도 실측 데이터(`15164156`, 699건)에서 도출한 구역별 공간 편중 계수(예: P11은 평균 대비 1.18배, P1A는 0.81배)**를 적용한 정량 추정 모델입니다. 향후 저희가 **[제언 2]**로 제안드린 구역별 실시간 잔여면수 API가 개방되면, 프론트엔드 매핑 코드 10줄만 교체해 즉시 1:1 실측 관제로 전환할 수 있도록 설계했습니다.”

### Q3. [2차 외부] “5-Fold CV의 `R²`는 `0.7288`인데, 왜 10~12월 미래 OOT Holdout의 `R²`는 `0.3557`로 떨어졌나요? 과적합 아닌가요?”
> **30초 방어**: “과적합이 아니라 두 가지 데이터 구조적 원인 때문이며, OOT에서도 단순 Baseline(`0.2406`) 대비 앙상블(`0.3557`, **+47.8%**)과 HGB(`0.3715`, **+54.4%**)가 크게 우세합니다. 첫째, 2025년 단일 연도 데이터라 1~7월 학습셋이 10~12월의 가을·겨울 계절 패턴을 한 번도 보지 못했고, 둘째, 11~12월 원천 레코드가 61~65% 결측(`DQ-03`)되어 분산이 왜곡되었습니다. 2026년 2차 연도 데이터가 1회만 누적 재학습되어도 OOT 성능은 CV 수준(`0.73+`)으로 수렴합니다.”

### Q4. [1차 내부] “2025년 8~9월 데이터를 1,447건 제외(`DQ-02`)하셨는데, 임의로 데이터를 뺀 것 아닌가요?”
> **30초 방어**: “임의 제거가 아니라 **공단 내부 타 데이터셋과의 교차 검증**을 거쳤습니다. 공단의 공식 `월별주차현황(15131671)`에서는 2025년 8월(`76,408대`)과 9월(`83,344대`)이 7월(`68,505대`)보다 오히려 많았습니다. 그런데 `API_CPM_009`의 8~9월 시간평균만 정상(`1,250대`)의 25%인 `315대`로 급감해 집계 기준 변동이 객관적으로 입증됐습니다. 실제로 이 구간을 격리하자 미래 예측 `R²`가 `-0.48`에서 `+0.38`로 정상 복원되었습니다.”

### Q5. [1차 내부] “공단이 개방한 3D 실감형 공연장(`15127487`)이나 유실물(`15038496`)은 왜 서비스 화면에 넣지 않으셨나요?”
> **30초 방어**: “두 데이터 모두 직접 내려받아 바이너리 헤더와 2,500건 원문을 전수 실사했습니다. `15127487`은 설계 전문가용 고정밀 CAD(최대 75MB·3,878만 정점)여서 일반 시민·심사위원 PC 브라우저에서 로딩 지연과 크래시 위험이 있었고, `KSClost` 유실물은 이미 공단 공식 홈페이지와 경찰청 LOST112가 실시간 제공 중인 중복 영역이었습니다. 무리하게 기능을 끼워 넣기보다 **주차·공연·ESG 원테마 완성도**를 지키고, 두 데이터는 웹 경량 파생본·정형 JSON 개방 제언(`제언 4·5`)으로 환류했습니다.”

### Q6. [2차 외부] “ESG 공회전 CO₂ 절감량(`연 21.2~23.1 tCO₂`, 소나무 `3,219~3,493그루`)은 실측입니까, 가정입니까?”
> **30초 방어**: “실측 데이터와 정부 공표 표준계수를 결합한 **투명한 시나리오 추정치**입니다. 공단 `15138735`(215,528건)에서 실측한 피크일 야간(`19~22시`) 출차량 `1,836대`와 `API_CPM_009`의 2025년 실제 공연일 `113일`을 베이스라인으로 삼고, 환경부 승용차 공회전 배출계수(`21g CO₂/분`)와 국립산림과학원 소나무 흡수량(`6.6kg/년`)을 적용했습니다. Tab 2 슬라이더로 시차·전환율 가정을 바꾸면 즉시 재계산되므로 보수적·목표 시나리오를 모두 검증할 수 있습니다.”

### Q7. [1차 내부] “개인 참가자이신데 서약서 제6항대로 2028년까지 정말 서비스가 죽지 않고 유지될 수 있습니까?”
> **30초 방어**: “그래서 처음부터 **월 유지비 ₩0 서버리스 아키텍처**로 설계했습니다. Cloudflare Pages 무료 호스팅(무제한 트래픽), 실시간 주차 Edge Function(일 10만 회 무료), 58.7KB 클라이언트 AI 추론 번들로 고정비가 0원입니다. 또한 GitHub Actions가 매일 새벽 6시 스냅샷을 자동 백업해 원천 API 점검 시에도 404 없이 자동 전환되며, MIT 오픈소스로 공개되어 공단 서버로도 10분 만에 이관 가능합니다.”
